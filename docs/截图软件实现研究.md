# Ashot：macOS 截图软件实现研究

研究日期：2026-09-29。Ashot 为当前目录名，暂作项目代号。

## 1. 结论与范围

用户已确定首版只做 macOS。建议采用 Swift 原生应用：SwiftUI 管设置和普通界面，AppKit 管截屏覆盖层、标注画布和贴图窗口；ScreenCaptureKit 采集，Core Graphics / Core Image 绘制，Vision 做本地 OCR。

产品主线是“快捷键 → 框选 → 标注 → 复制、保存或贴图”。先把每天使用的这条链路做好，再加入长截图和录屏。第一版不用账户、云端、AI 服务、跨平台壳或插件系统。

建议最低 macOS 14；录屏阶段如果要用系统直接写文件及麦克风采集，作为 macOS 15+ 增强功能。不要为了兼容 iShot 的 macOS 10.13 最低要求而建立两套截图引擎。最低版本是本研究建议，尚未被用户单独确认。

本次完成的是实现研究与设计，没有创建应用代码，也没有构建可运行原型。

## 4. 产品交互建议

### 截图主流程

1. 菜单栏常驻；首次启动显示简短引导。只有用户第一次截图时才请求屏幕访问权限。
2. 快捷键触发后采集当前显示器画面，出现十字线、放大镜和尺寸提示。
3. 拖动选择区域，支持边缘调整；Space 切换窗口选择，Esc 取消。
4. 选区旁显示紧凑工具栏：箭头、框、文字、遮盖、更多；右侧为贴图、保存、复制。
5. Enter 复制，Command+S 保存，Command+Z 撤销；文本编辑状态下 Enter 应优先交给文本框，避免误结束截图。
6. 复制或保存后退出覆盖层，恢复之前应用的焦点；失败时保留编辑结果并给出重试入口。

快捷键可自定义。默认组合需在当前系统和常见应用中检查冲突，不能照搬本机 iShot 的 Option+A：两款软件并存时会冲突。

### 长截图流程

框选可滚动内容 → 长截图 → 用户滚动 → 边采集边显示累计高度 → 完成 → 进入同一个标注编辑器。

低置信度时显示“暂未对齐，请稍慢滚动或返回上一位置”，保留已拼接内容，提供“保留到这里”“重试”“取消”。不要直接退出，也不要把疑似错位图当作成功结果。

### 设计原则

- 截图结果可直接继续编辑，普通截图与长图用同一套工具。
- 主界面不展示技术参数；高级设置里才放输出缩放、颜色配置等。
- 贴图一定能找回：菜单中可显示全部、关闭全部，并逐个列出窗口。
- 设置首版只分“通用、快捷键、截图与输出”；不要先铺满功能侧栏。
- 优先保证中文输入、键盘操作、工具提示和屏幕阅读器标签。

## 5. 技术选择与系统边界

| 方案 | 优点 | 代价 | 判断 |
|---|---|---|---|
| Swift + SwiftUI + 局部 AppKit | 原生窗口与权限集成，直接使用系统图像能力 | 需要认真处理 AppKit 生命周期和坐标 | 推荐 |
| 纯 SwiftUI | 普通设置页方便 | 特殊窗口、精细鼠标交互、文本焦点仍常需 AppKit | 不强求纯 SwiftUI |
| Electron / Tauri | 熟悉网页技术时设置界面开发快 | 屏幕采集、贴图、快捷键仍需平台桥接，增加边界 | 仅做 macOS 暂无明显收益 |
| Qt / C++ | 后续跨平台可共享部分逻辑 | 目前没有跨平台需求，macOS 集成仍需适配 | 暂不引入 |

AppKit 仅承担它擅长的窗口和事件工作：`CaptureOverlayController` 持有临时 `NSWindow`，`PinWindowController` 持有 `NSPanel`；普通设置、列表、属性面板仍用 SwiftUI。SwiftUI 和 AppKit 共享一个文档状态，不各存一份标注数据。

### API 版本分层

以下版本已核对本机 SDK 的 `API_AVAILABLE`，发布前还需在对应系统运行测试：

| API | macOS 起始版本 | 使用策略 |
|---|---|---|
| ScreenCaptureKit 基础采集 | 12.3 | 框架基础，不等于所有新 API 都可用 |
| SCScreenshotManager.captureImage(contentFilter:configuration:) | 14.0 | 首版单帧截图主路径 |
| SCContentFilter.pointPixelScale | 14.0 | 辅助建立点与像素的映射 |
| SCRecordingOutput、captureMicrophone | 15.0 | 后续基础录屏路径 |
| SCScreenshotManager.captureImage(in:) | 15.2 | 可选便利 API，不作为兼容 14 的主路径 |
| SCScreenshotConfiguration、captureScreenshot | 26.0 | 未来增强，按 availability 隔离 |

Apple 的截图 API 与系统内容选择器介绍见 [WWDC23](https://developer.apple.com/videos/play/wwdc2023/10136/)；录屏、麦克风和 HDR 增强见 [WWDC24](https://developer.apple.com/videos/play/wwdc2024/10088/)。不要因为开发电脑是 macOS 27，就无意使用新 API 破坏最低版本支持。

## 6. 截图引擎：最先验证的部分

### 推荐流程

`Shortcut → CaptureSession → Permission → Target/DisplaySnapshot → Capture → Selection → Document → Export`

快捷键触发后先取一份可信的画面，再在它之上显示框选覆盖层。选区预览和最终导出都基于这份画面，避免用户框选期间页面变化，导致“看到的”和“保存的”不同。

普通截图用 `SCScreenshotManager`；只有长截图、录屏等确实需要持续帧的功能才启动 `SCStream`。结束或取消后释放帧、事件监听和窗口，空闲时不保留持续采集。

窗口模式需要明确两种含义：按窗口矩形裁切屏幕，只能得到屏幕上可见内容；按独立窗口过滤采集，则由系统提供该窗口画面。产品应选定一种，不能混用。首版推荐独立窗口采集，并验证被遮挡、最小化、窗口关闭时的实际行为。

### 坐标设计

明确分开：桌面全局坐标、显示器局部逻辑点、图像像素坐标、编辑器缩放坐标。统一由 `CoordinateMapper` 转换。

- AppKit 与图像 API 的原点、Y 轴方向并不总一致；每个边界显式转换。
- 不用 `NSScreen.main` 的一个倍率处理全部显示器。
- 输出尺寸从该显示器实际采集像素与逻辑区域建立映射，不能一律乘 2。
- 四舍五入策略统一；框选边缘应落到明确像素边界。
- 左侧、上方显示器可能有负坐标；处理旋转屏和非连续显示布局。
- 显示器热插拔或分辨率变化使会话失效时，取消并提示重选；不沿用过期变换。
- “上次区域”保存显示器标识、逻辑矩形；显示器消失或矩形越界时让用户重选。

首版支持在任一显示器内框选，但先不支持一张选区跨越混合缩放显示器。跨屏后续需制定统一输出像素密度及重采样策略；这是产品边界，不是简单拼上两张图。

### 避免把自己的界面截进去

优先先采集、后显示覆盖层；流式采集通过 `SCContentFilter` 排除工具栏和覆盖层窗口。排除规则按窗口角色制定，不能简单排除自己整个应用，否则用户想截取已贴出的图片时也会丢失。

不能只依赖 `NSWindow.sharingType = .none`：Apple 将该值标为不再使用的旧常量。[Apple 文档](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum)

首版导出 SDR/sRGB，明确做颜色转换并嵌入配置，不能只改颜色标签。HDR、Display P3 与原始宽色域输出后置，取色结果要注明所属色彩空间。

## 7. 标注与编辑器

文档建议保持三部分：原图资产、标注对象列表、输出设置。标注对象至少包括稳定 ID、类型、几何、颜色、粗细、透明度、层级；文字额外包含内容、字体和排版信息。

所有几何使用图像坐标，缩放只改变视图变换。编辑器和导出复用同一渲染器，避免保存后箭头、字体、马赛克与屏幕不一致。

### 各工具实现

- 矩形、椭圆、线条、箭头：Core Graphics 路径；箭头头部随线宽变化，保留最小尺寸。
- 自由画笔：记录采样点，简化和平滑路径；预览阶段局部重绘。
- 文字：编辑时用原生文本控件承接中文输入法，导出用确定的字体和排版；确认编辑、撤销、焦点切换必须单独测试。
- 高亮：透明色块或路径，提供可预测的混合方式。
- 步骤编号：文档内统一编号策略；删除是否重排需明确，不能随机变化。
- 马赛克：对原图的指定区域做像素化再合成，避免每一帧处理整张图。
- 隐私遮盖：另提供完全不透明色块，导出时烘焙覆盖区域。普通导出的 PNG/JPEG 不包含可恢复的原始图层；可编辑工程文件则明确仍可能保留原图。

拖动和调整作为一个撤销操作提交，不要每个鼠标移动事件都生成一份全尺寸位图。通过 `UndoManager` 记录对象级修改；撤销后继续编辑应清空不再有效的重做分支。

首版不需要设计成图像处理平台，也不需要 GPU 自定义着色器；先用系统绘制和 Core Image，依据性能数据再优化。

## 8. 贴图、保存、历史与取色

### 贴图

用 `NSPanel` 控制浮动层级、拖动、透明度和是否参与所有 Spaces。平常不抢键盘焦点，需要文字编辑时才切换到可编辑状态。全屏应用、Mission Control、Stage Manager 下的行为必须实机验证。

穿透鼠标模式需要对应的快捷键或菜单项恢复，否则窗口会变成无法操作的悬浮物。首版可以暂不做穿透。贴图缩放复用原图与低分辨率预览，多个贴图不能各持有多份全尺寸缓存。

### 输出与持久化

- `NSPasteboard` 写入标准图片表示，实测粘贴到微信、浏览器编辑器和预览；不要用粘贴板读取成功代替目标应用验收。
- `ImageIO` 导出 PNG/JPEG；JPEG 不支持透明，导出时明确背景色。
- `NSSavePanel` 选路径，失败保留文档；命名避免重名覆盖，先临时写入，完成后原子替换目标。
- 用户明确选择的自动保存目录持久化授权；不靠读取整个桌面目录解决单文件保存。
- 第一版不自动永久留存所有截图。历史库作为后续可选项，支持容量上限、删除与原图保留说明。
- 小规模历史可先用 JSON 索引 + 独立图片文件和缩略图；需要 OCR 搜索和更大规模时再引入 SQLite。

### 取色

首版可以从冻结截图取像素，显示 HEX、RGB，避免另起常驻采集器。若提供实时取色，可评估系统 `NSColorSampler`。输出统一到指定色彩空间，放大镜不用平滑插值，避免显示的像素颜色被混合。

## 9. OCR、二维码与翻译

OCR 使用 `VNRecognizeTextRequest`；先检测运行系统支持的语言，按中英文实际内容设置识别优先级。后台处理，不阻塞框选和编辑；保存文本及对应区域，低质量识别允许用户修改。

Vision 的文字识别在设备本地完成，可配置快速/准确识别及语言，文字框需要坐标转换。[Apple OCR 文档](https://developer.apple.com/documentation/vision/recognizing-text-in-images)

二维码与文字分开呈现，二维码识别到地址后由用户决定是否打开；避免图片里有一个二维码就吞掉全部文字识别结果。

多列、表格、代码缩进是排版问题，不能把 Vision 返回的文本简单拼接就宣称完成“表格 OCR”。首版只承诺普通段落识别及保留/移除换行。

翻译后置，可优先评估系统 Translation framework 的语言支持、语言包和系统版本；若以后接云服务，单独设计用户主动调用、目标服务说明、费用与失败处理。框架入口见 [Apple Translation](https://developer.apple.com/documentation/translation/)。本次没有核实 iShot 使用了哪家翻译服务。

## 10. 长截图：独立的高风险模块

官方教程明确建议框选全部可滚动的静态内容，并列出了固定区域、动态内容、横向位移和平滑滚动工具引起的问题。这说明这些场景必须加入测试；不能由教程推导它的具体拼接算法。[iShot 官方教程](https://www.better365.cn/ishot/scrollscreenshot.html)

### 推荐算法路径（我们的设计）

1. 用户选择滚动区域，开始低帧率屏幕流；流式帧与截图工具界面分离。
2. 检测画面变化，去掉重复帧，等待合适的稳定帧；保留有限帧队列。
3. 灰度或边缘缩略图上估计垂直位移，再在全分辨率重叠区域校验。
4. 原型可以试用 Vision 平移配准，或用多条纵向内容带做归一化相关匹配；比较真实数据后再选择。
5. 对多个内容带求一致位移，排除鼠标、滚动条、视频块等干扰；剔除变化异常的区域。
6. 用独立指标评估可信度：重叠误差、候选峰值差、各条带位移一致性、有效纹理量。
7. 可信时只追加新增像素；不可靠时暂停接收拼接，不静默跳过缺失内容。
8. 用户结束后交给统一编辑器；导出前展示拼接结果，可回退最后一次追加。

Vision 提供图像平移配准请求，但并不提供完整的通用长截图功能。[Apple 配准文档](https://developer.apple.com/documentation/vision/vntranslationalimageregistrationrequest)

### 分阶段限定

- 第一阶段：单个静态页面，竖直向下、用户手动滚动，选区避开固定标题栏。
- 第二阶段：固定区域检测与裁切、有限的反向滚动、动态区域屏蔽、失败后继续。
- 第三阶段：自动滚动；单独验证输入控制权限、目标窗口焦点、退出响应及沙盒可行性。
- 任意应用的隐藏页面没有统一获取接口；不能用一个 WKWebView 全页截图证明外部 Safari、微信或 PDF 都能长截图。
- 低纹理白区、重复表格行可能产生多解；宁可请求减速/重选，也不能假设匹配最高分就是正确。
- 丢弃帧时必须检查相邻保留帧是否仍有足够重叠；单纯“只处理最新帧”可能直接丢掉内容。

### 内存和导出

4000 × 50000 像素的 4 字节像素图，仅原始像素就约 763 MiB；两个完整副本约 1.49 GiB，还没有算预览和滤镜缓存。这是尺寸算术，不是性能实测。

长图按条带存储，预览只用降采样结果；限制尺寸和内存预算。最终 PNG 编码是否能在预算内完成需要实测，不能认为分块保存就自动解决了编码峰值。超限应提示缩放或分段导出，不进入无限内存增长。

## 11. 录屏与录音

把录屏作为独立阶段，复用目标选择和权限管理，但不复用截图会话的生命周期。

- 基础录屏：macOS 15+ 可评估 `SCStream + SCRecordingOutput`。
- 要支持 macOS 14 的录屏、暂停去除时间段、自定义混音或复杂效果时，评估 `SCStream + AVAssetWriter`，承担时间戳和输出完成处理。
- 新系统的 `captureMicrophone` 不可直接调用到旧系统；旧系统若需要麦克风，另走 AVFoundation 采集并对齐时钟。
- 系统音频与麦克风的单轨混音、双轨输出要做明确选择；不承诺所有播放器都自动混合两条音轨。
- 系统停止共享、目标窗口关闭、磁盘满、锁屏、睡眠、麦克风拔出都是结束/恢复路径。
- 只有文件写入完成回调后才能显示“保存成功”。暂停不能仅停止绘制预览，必须正确处理实际媒体时间线。
- 摄像头叠加、录屏标注、GIF、HDR、独立录音先后置。

Apple 已提供屏幕、系统声音、麦克风采集及直接写文件能力，具体使用受系统版本约束。[WWDC24](https://developer.apple.com/videos/play/wwdc2024/10088/)

## 12. 权限、签名与发布

| 操作 | 策略 |
|---|---|
| 截取其他应用画面 | 首次使用检查屏幕访问，用户点击后请求；采集失败仍须处理 |
| 全局快捷键 | 优先使用专用热键注册，不为基础快捷键索取辅助功能权限 |
| 用户手动长截图 | 尽量只观察捕获帧，不依赖全局键盘/鼠标监听 |
| 自动滚动或操作其他应用 | 作为后续独立能力验证对应权限与沙盒限制 |
| 保存文件 | 系统面板或用户指定目录授权 |
| 麦克风/摄像头 | 启用对应功能时才请求 |
| OCR | 本地执行，不要求联网 |

权限状态不是一个永久的 Bool。需要区分未授权、被拒绝、访问已被撤销、目标失效和其他采集错误。进入设置返回后重新检查；如果某系统要求重启生效，明确提示，不能不停弹窗。

热键可考虑 [KeyboardShortcuts](https://github.com/sindresorhus/KeyboardShortcuts)：项目声明兼容沙盒和 Mac App Store、无需额外权限，并提供冲突提示。作为外部依赖时固定版本、保留许可证；不为首版再加多个快捷键库。

先做本地可运行 `.app`；对外直接分发阶段使用稳定 Bundle ID、Developer ID 签名及公证，升级后测试权限是否正常继承。App Store 和直接分发不是同一条验收链路，自动滚动等能力在承诺上架前单独验证。[Apple 分发文档](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)

## 13. 代码组织建议

先一个应用目标，按职责分目录，不先拆成微服务、插件或多个独立工程。

| 模块 | 职责 | 不能承担的职责 |
|---|---|---|
| App / Settings | 菜单栏、设置、入口 | 图像算法 |
| Capture | 权限、屏幕/窗口枚举、单帧和流采集 | 编辑器状态 |
| Selection | 覆盖层、框选、坐标映射 | 文件持久化 |
| Document | 原图引用、标注、撤销、输出配置 | 系统窗口控制 |
| Editor / Rendering | 工具交互、预览、导出绘制 | 截取其他应用 |
| Pin | 浮动窗口与显示管理 | 再造一套标注模型 |
| Export | 剪贴板、文件编码与保存 | 快捷键管理 |
| OCR / Stitch / Recording | 各自的后台任务与会话 | 隐式修改全局状态 |

最小数据模型：`CaptureTarget`、`DisplaySnapshot`、`CaptureFrame`、`ScreenshotDocument`、`Annotation`、`ExportOptions`。

会话状态建议：`idle → preparing → selecting → editing → exporting → finished`，长截图和录屏持有独立子会话。任意阶段均可取消或失败；清理统一执行。异步任务带 session ID，已取消会话的回调不得再次弹出编辑窗口。

UI 状态由主线程管理；OCR、配准和编码在后台处理，支持取消和背压。后台任务不要持有已经关闭的窗口。

## 14. 实施阶段与验收

下面是开发顺序与验收门槛，不是已经完成的功能。先完成前一阶段再扩大范围。

| 阶段 | 交付物 | 必须真实验证 |
|---|---|---|
| A：技术样机 | 菜单栏、快捷键、区域/窗口采集、复制与保存 | 尺寸、颜色、自身界面排除、取消、权限拒绝后恢复 |
| B：日常可用版 | 核心标注、文字、遮盖、撤销重做、贴图、设置 | 截图→编辑→保存→重新打开；粘贴到真实应用 |
| C：效率增强 | 本地 OCR、取色、预设尺寸、上次区域、外部编辑器 | 中英文识别、负坐标显示器、目录授权恢复 |
| D：长截图 | 手动竖直拼接、实时预览、错误恢复 | 已知内容逐行比对，无漏行、重复、错位 |
| E：录屏与分发 | 录制、声音、停止收尾、签名安装包 | 完整播放、音画同步、系统中断、全新账户安装 |

### 建议目标（待样机测量，不是现有性能数据）

- 同一台参考机器、已授权、单屏暖启动，快捷键到可框选画面 P95 目标不超过 250 ms；首次授权和冷启动单独计量。
- 中等截图约 2000 × 1200 像素、常见标注，复制/保存 P95 目标不超过 500 ms；注明编码格式及是否包含磁盘时间。
- 空闲不持续采集，CPU 接近空闲基线；记录空闲内存及 100 次截图取消循环后的残留变化。
- 100 次快速触发/取消无悬浮层残留、无抢焦点、无重复完成回调。
- 长截图建立固定样本集：普通文章、表格、代码、PDF、聊天式列表、固定标题栏、动图干扰、低纹理空白；简单静态场景逐行完整，困难场景失败应可恢复且不静默错拼。

### 自动化与实机各测什么

- 单元测试：坐标转换、像素边界、撤销重做、路径几何、拼接位移/误差判定、文件命名。
- 图像测试：用自建文字与色块图验证导出和拼接，固定字体与颜色配置；必要时容忍抗锯齿差异，不能把所有差异忽略。
- 真实桌面：系统权限、热键冲突、全屏/Spaces、多屏、中文输入、剪贴板目标应用、外接屏热插拔。
- 安装测试：签名后 `.app` 的首次启动、升级、权限、保存路径和卸载数据策略。
- 至少覆盖最低支持版本和主要目标版本；本机 macOS 27 的测试不能代表 macOS 14。

第一项开发工作应是阶段 A 样机。只有真实截到正确像素、可靠退出并成功交给其他应用后，才值得继续做完整视觉设计与功能堆叠。
